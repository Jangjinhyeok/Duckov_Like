# Escape From Duckov UI 레퍼런스 관찰

이 문서는 원작의 화면 구성·배치·흐름을 관찰한 기록이다. 아트·아이콘·글꼴·로고는 가져오지 않는다.
원작 스크린샷은 저작물이므로 저장소에 넣지 않는다.

## 관찰 방법과 한계

- 2026-10-11, 사용자가 실행한 원작(표시 버전 v2.3.30, 2560×1440)을 사용자가 직접 조작했다.
  AI는 게임 창을 2초 간격으로 캡처해 화면이 바뀐 33장을 읽었다. AI가 원작에 입력을 보내지는 않았다.
- 캡처는 세션 scratchpad에만 있고 저장소에는 없다.
- 화면 오른쪽 위의 FPS·GPU·CPU 표시는 NVIDIA 오버레이이며 원작 UI가 아니다.
- 관찰은 이번에 지나간 화면에 한정한다. 버튼 동작, 내부 구현, 저장 형식은 추정하지 않는다.

## 흐름

```
스플래시 → (클릭) 메인 메뉴 → 계속하기 → 로딩 → 베이스먼트
베이스먼트 → (출구) 로딩 → 바깥 맵 → (거울 상호작용) 커스터마이징 → 확인 → 바깥 맵
```

원작은 커스터마이징을 시작 흐름이 아니라 맵 안의 거울 상호작용으로 연다(이번 관찰 기준).
이 프로젝트는 사용자가 정한 흐름(타이틀 → 게임 시작 → 커스터마이징 → 베이스먼트)을 따른다.

## 타이틀·메인 메뉴

| 요소 | 관찰 |
| --- | --- |
| 스플래시 | 흐린 3D 배경, 화면 중앙의 로고, 하단 중앙에 "화면을 클릭하여 계속하기" |
| 메뉴 전환 | 클릭하면 같은 배경을 유지한 채 로고가 사라지고 메뉴가 나타난다 |
| 메뉴 배치 | 화면 왼쪽(가로 약 6%, 세로 약 18~85%)의 세로 열. 버튼마다 길이가 다른 둥근 pill |
| 위계 | 주 동작 "계속하기"만 초록·가장 큰 크기. 일반 항목은 파랑. 위험 항목 "길게 눌러 세이브 데이터 삭제하기"는 빨강 |
| 항목 | 계속하기, 세이브 슬롯(번호와 상태), 세이브 삭제(길게 누르기), Mods, 설정, 제작진, 게임 종료. 모두 아이콘 + 텍스트 |
| 기타 | 오른쪽 아래에 작은 버전 표기 |

## 로딩

검은 전체 화면, 하단 중앙의 "로딩 중...", 그 아래 한 줄짜리 팁.

## 베이스먼트와 이후 화면(요약)

6번 작업(UI 구조 개편)에서 다시 자세히 본다.

- HUD: 왼쪽 위에 시계와 다음 이벤트 카운트다운, 오른쪽 위에 조작 설명 키, 하단 중앙에 체력·자원 원형 게이지와
  번호가 붙은 퀵슬롯 줄, 왼쪽 아래에 현재 장소, 오른쪽 아래에 거리 표시.
- 퀘스트: 왼쪽에 진행 중/완료 탭과 목록이 있고, 배경 장면은 흐려진다.
- 인벤토리 + 창고: 왼쪽 패널은 캐릭터 장비 슬롯과 가방 격자, 오른쪽 패널은 "창고"다. 창고에는 카테고리 탭, 세로 필터 띠, 격자가 있다.
  상단 가운데에 화면 전환 아이콘 줄이 있고, 하단 퀵슬롯은 계속 보인다.
- 커스터마이징: 왼쪽에 부위 탭(머리, 눈, 헤어, 부리, 날개, 꼬리, 발)이 있고, 그 옆에 선택한 부위의 조절 열이 있다.
  가운데에는 거울 속 캐릭터 미리보기, 오른쪽 아래에 포기(빨강)와 확인(초록, 큼), 왼쪽 아래에 프리셋과 클립보드 버튼이 있다.
- 일시정지: 배경이 흐려지고, 왼쪽에 "일시정지" 제목과 세로 버튼 목록, 그 아래 빨간 위험 버튼이 있다.

## 베이스먼트 조작(2026-10-11, Computer Use 직접 관찰)

AI가 Computer Use로 원작 창을 직접 조작했다. 기존 세이브의 "계속하기"로 들어가 베이스먼트에서 걷기만 했고,
잠자기·아이템 사용·출격처럼 세이브에 영향을 주는 동작은 하지 않았다.

| 요소 | 관찰 |
| --- | --- |
| 로딩 뒤 | 로딩이 끝나면 "화면을 클릭하여 계속하기" 확인을 한 번 더 받는다 |
| 조작 설명(O) | Tab 가방, Space 구르기, Shift 달리기, RMB 조준, LMB 사격/공격, R 재장전, Y 시점 전환, C 무기 넣기, P 촬영 모드. 오른쪽 위 세로 목록 |
| 이동 | WASD는 화면 기준이다(W를 누르면 화면 위로 이동) |
| 카메라 | 고정 각도의 높은 탑다운에 방이 비스듬히 보이도록 yaw가 회전돼 있다. 캐릭터를 따라가며 조준 커서 쪽으로 약간 앞서 간다 |
| 조준 | 마우스 커서 위치에 십자선이 있고 캐릭터에서 커서까지 조준선이 그려진다 |
| 캐릭터 표시 | 머리 위에 빨간 체력 바 |
| 상호작용 | 상호작용 가능한 물체에 ◎ 표시가 항상 보인다. 가까이 가면 물체 옆에 "◎ 잠자기(시간 보내기) [F]" 같은 pill 프롬프트가 뜬다. 키는 F |

## HUD·인벤토리 상세(2026-10-14, Computer Use 직접 관찰)

AI가 Computer Use로 원작(v2.3.30, 2560×1440)을 조작했다. "계속하기"로 베이스먼트에 들어가 걷기, Tab 열고 닫기,
아이템 위 마우스 올리기만 했다. 드래그·아이템 사용·잠자기처럼 세이브가 바뀌는 동작은 하지 않았다.

### HUD(베이스먼트)

| 위치 | 요소 |
| --- | --- |
| 왼쪽 위 | 큰 디지털 시계(07:05)와 그 옆 작은 두 줄(낮/날씨). 아래 줄에 "다음 폭풍 도착 카운트다운: 112:55"와 원형 아이콘. 배경 패널 없이 글자만 |
| 오른쪽 위 | "조작 설명" 글자와 흰 키 배지 [O] |
| 왼쪽 아래 | 작은 어두운 pill에 장소 아이콘 + "기지" |
| 아래 중앙 | 하트 + 빨간 체력 막대(858/858), 파랑(물)·주황(에너지) 원형 게이지, 무기 슬롯 1·2(선택된 슬롯은 주황 테두리, 위에 탄약 이름과 [T], 37/140), V 슬롯, 퀵슬롯 3~8. 슬롯마다 아래에 흰 숫자 키 배지 |
| 오른쪽 아래 | 조준 아이콘 + 커서까지 거리(05 M). 커서가 멀면 아이콘이 주황, 가까우면 초록 |
| 화면 중앙 | 마우스 커서 위치의 십자선. 캐릭터 머리 위 빨간 체력 막대 |

- 상호작용 가능한 물체에는 작은 흰 ◎가 늘 붙어 있다. 범위 안에 들어가면 그 ◎ 자리에서 오른쪽으로 파란 pill이 뻗는다:
  `◎ 잠자기(시간 보내기) [F]`. 키는 pill 오른쪽 끝의 흰 둥근 사각 배지다. 프롬프트는 화면 고정이 아니라 물체 위치에 붙는다.
  범위는 좁아서 침대 머리맡까지 붙어야 떴다.
- HUD 글자는 대부분 배경 없이 그림자만 있고, 작은 정보(장소, 거리)만 어두운 pill 위에 있다.

### Tab 인벤토리(베이스먼트)

베이스먼트에서는 Tab만으로 왼쪽 캐릭터 패널과 오른쪽 창고가 함께 열린다. 3D 장면은 흐려지지 않고 어두워지지도 않는다.

| 위치 | 요소 |
| --- | --- |
| 위 중앙 | 아이콘 탭 6개(가방·캐릭터·북마크·지도·열쇠·노트). 선택된 가방 탭은 흰 원 배경, 아래에 소지 무게 45.6/112.8kg. 아이콘 클릭으로는 전환되지 않았다(전환 키 미확인) |
| 왼쪽 위 | 돈 두 가지를 어두운 pill 두 개로(₩ 249,628 / 지폐 0) |
| 왼쪽 패널 | 반투명 남색 둥근 패널. "장비" 제목 아래 5열 2줄 슬롯(총기, 총기, 근접 무기, 머리, 신체 / 얼굴, 헤드폰, 가방, 토템, 토템). 슬롯은 아이콘 칸 + 아래 슬롯 이름. 빈 슬롯은 흐린 아이콘만 |
| 왼쪽 패널 아래 | "가방 (22/85)" 제목과 오른쪽 버튼 두 개 "전부 창고에 보관"·"정리". 그 아래 5열 격자 |
| 왼쪽과 장면 사이 | 좁은 세로 열에 특수 슬롯 4개(야간투시경, 수집기, 주사기 케이스, 지갑)와 펫(발바닥) 버튼 |
| 왼쪽 아래 | "소지 중량" 막대와 45.6/112.8kg |
| 아래 중앙 | "아이템을 슬롯으로 드래그하여 퀵슬롯을 설정하세요" 안내와 퀵슬롯 3~8 |
| 오른쪽 패널 | 큰 제목 "창고 (752/810)". 카테고리 아이콘 탭 한 줄(전체 ∞, 총, 탄약, 방어구, 근접, 토템, 의료, 음식, 도구). 선택된 탭은 주황 배경. 그 아래 "창고 (752/810)"와 "정리" 버튼, 5열 격자 |
| 오른쪽 패널 왼쪽 | 페이지 번호 세로 열 0~23(현재 페이지는 주황), 위아래 화살표와 W/S 키 배지 |

- 원작의 가방과 창고는 **모든 아이템이 한 칸인 목록형**이다(용량은 칸 수 22/85). 이 프로젝트의 크기·회전이 있는 그리드 배치와는 다르다.
- 아이템 칸: 어두운 둥근 사각, 얇은 밝은 테두리. 가운데 큰 아이콘, 오른쪽 아래 작은 흰 이름(길면 …), 그 위에 수량 숫자.
  등급은 아이콘 외곽선 색(파랑, 보라)으로 보인다. 내구도가 있는 항목은 이름 위에 짧은 파란 막대.
- 툴팁(마우스 올림): 칸 오른쪽에 반투명 검은 패널. 이름(큰 글자), 무게, 설명 한 줄, 속성 표(이름-값 두 열).
  그 오른쪽에 조작 키 열: [F] 줍기/놓기, [X] 버리기, [Ctrl]+드래그 분할, [RMB] 메뉴, [L] 정렬 잠금/해제, [N] 표시, [3]~[8] 퀵슬롯.
- Tab을 다시 누르면 닫힌다.

### 드래그(사용자 직접 조작, AI는 2초 간격 캡처만)

사용자가 Tab 인벤토리에서 아이템을 끌었고 AI는 축소 화면 18장을 읽었다. 2초 간격이라 순간 표시는 놓쳤을 수 있다.

- 끄는 동안 반투명한 아이템 칸(아이콘·이름 포함)이 커서를 따라간다. 원래 칸은 비어 보인다.
- 창고 패널 위에서는 반투명 칸이 커서 아래 칸에 겹쳐 놓일 자리를 보여 준다. 칸 테두리 색 변화는 이 해상도에서 확인하지 못했다.
- 끄는 중에 창고의 페이지 번호 위에 머물면 그 페이지로 넘어간다(22 → 21).
- 놓으면 양쪽 개수가 바로 바뀐다(가방 22/85 → 21/85, 창고 752/810 → 753/810). 옮긴 결과는 사용자가 직접 정리했다.
- 놓을 수 없는 자리의 표시(빨강 등)는 이번에 관찰하지 못했다.

## 이 프로젝트에 옮긴 것

| 원작 구조 | 이 프로젝트 |
| --- | --- |
| 스플래시 → 같은 배경 위 메뉴 전환 | `UTitleScreenWidget`의 두 상태 |
| 왼쪽 세로 pill 메뉴, 주 동작만 초록·크게 | 게임 시작(초록·큼), 게임 종료(파랑). 기능이 없는 항목은 만들지 않음 |
| 검은 로딩 화면, 하단 중앙 문구 | `ULoadingScreenWidget`. 팁 문구는 내용이 없어 생략 |
| 로고 | 텍스트 타이틀 "DUCKOV LIKE"로 대체 |
| 화면 기준 WASD, Shift 달리기, 고정 각도 탑다운 카메라 | `ADuckovCharacter`(설계결정기록 023). 조준·구르기·look-ahead·상호작용 프롬프트는 아직 없음 |
| 가까이 가면 뜨는 "동작 [F]" pill 프롬프트, 키 F | `UInteractionPromptWidget`(설계결정기록 024). 위치는 물체 옆이 아니라 화면 아래 중앙, 상시 ◎ 표시는 없음 |
| 물체의 ◎ 자리에서 뻗는 파란 pill `◎ 동작 [F]` | 2026-10-14부터 물체에 붙는 screen space widget(설계결정기록 025). 물체마다 늘 보이는 ◎는 없음 |
| 오른쪽 위 "조작 설명 [O]", 왼쪽 아래 장소 pill | `UGameHudWidget`(설계결정기록 025). O로 키 목록을 펼친다. 장소는 기지/레이드 구역 |
| 시계·폭풍·체력·자원·무기·퀵슬롯·조준 거리 | 옮기지 않음. 이 게임에 해당 기능이 없다 |
| 베이스먼트의 Tab: 왼쪽 캐릭터(장비·가방), 오른쪽 창고 | I로 같은 배치(설계결정기록 026). 레이드에서는 창고 패널을 감춘다. 목록형이 아니라 크기·회전 그리드를 유지 |
| "가방 (22/85)" 머리줄과 "전부 창고에 보관"·"정리" | 그리드라서 차지한 칸/전체 칸. 두 버튼 모두 실제로 동작 |
| 아이템 칸: 어두운 둥근 칸, 오른쪽 아래 수량·이름, 긴 이름 말줄임 | 같은 구성. 아이콘은 없어 이름 글자만 |
| 툴팁의 조작 키 열 | 툴팁 글자 끝에 조작 키 안내 줄. 별도 툴팁 패널은 없음 |
| 커스터마이징: 왼쪽 부위 탭과 옆 조절 열, 가운데 거울, 오른쪽 아래 포기(빨강)·확인(초록, 큼), 왼쪽 아래 프리셋·클립보드 | `UCustomizationScreenWidget` 같은 배치(2026-10-15). 탭은 조절이 있는 머리·눈·부리·몸통만. 왼쪽 아래는 초기화와 개발용 실패 시험. 유형은 숫자·화살표 대신 A/B 버튼 |
