### 구현과 선택

- `UInventoryModel::TrySplit`가 수량·정의·공간을 검증하고 같은 컨테이너의 row-major 첫 빈자리에 분할한다.
  원본은 ID·위치·회전을 유지하고 수량만 줄어든다. 새 스택은 정의·회전을 복사하고 새 ID를 받는다.
  성공은 `Updated` 원본과 `Added` 새 항목을 한 ChangeSet으로 알린다.
- 실패는 아이템·점유 cache·allocator·알림을 보존한다. ID는 배치 검증이 끝난 뒤 발급한다.
  분할 ID 정책은 [스택 분할의 식별자와 원자적 반영](../architecture/018-stack-split.md)에 기록했다.
- 수량이 2 이상인 아이템의 **Shift+클릭 → 수량 입력 → 확인/Enter**로 분할한다. 기본값은 절반(내림),
  허용 범위는 1부터 원본 수량-1까지다. 소수·음수·빈 값·정수 범위 초과는 거부한다.
- 수량창이 열린 동안 뒤쪽 grid·정렬·닫기 button을 비활성화한다. 취소/Back은 창을 닫고 focus를 복구한다.
  전체 화면 비활성화와 원본 ItemVM 변경·제거·reset에서도 선택과 delegate를 정리한다.
  공간 부족이면 창·수량·오류를 유지한다. 새 스택은 기존 드래그로 이동할 수 있다.
- View는 입력과 임시 선택, InteractionVM은 명령 전달·실패 문구, Model은 실제 수량·ID·배치를 소유한다.
  기존 Canvas에 native 수량창을 추가하므로 저장된 WBP·map·Config·module 의존성은 바뀌지 않았다.
- AI 판단: 목적지 선택을 포함한 별도 분할 drag보다 같은 컨테이너 분할 후 기존 drag를 재사용했다.
  원본 컨테이너가 가득 차면 반대쪽에 빈자리가 있어도 분할할 수 없다. 자동 병합·회전은 없다.
