# M3 작업 기록

## 2026-09-28 — 첫 vertical slice: World Loot → Bag → Inventory UI

### 범위와 구현

- 사용자 요청: 첫 loot 획득 경로의 구현·검증만 수행. extraction/stash commit 등 다음 slice는 제외.
- Risk LOW. 기준은 clean `main` / `af3b07ad96e86198fce52fe255b94ad5d0a4b886`이며 현재 변경은 미커밋이다.
  기존 API·저장 형식·Model ownership·UI 갱신 구조를 보존하는 추가 API 범위로 판단했다.
- `UInventoryModel::TryAdd`가 정의·수량·first-fit 배치를 검증하고, 기존 allocator로 ID를 발급한 뒤
  candidate container를 commit한다. 실패는 container/cache/allocator를 보존하고 통지를 내지 않는다.
  기존 `Apply`의 post-commit Added ChangeSet과 재진입 guard를 사용한다.
- `AWorldLootActor`의 domain payload는 DefinitionTable/DefinitionRowName/Quantity뿐이다.
  controller의 `TryPickupLoot`가 Bag policy를 적용하며 성공 후에만 Actor를 소비·숨김·Destroy한다.
  callback 재진입과 이미 소비된 loot의 중복 획득은 거부한다.
- `E`/console `PickupNearestLoot`는 Pawn 주변 250 units 내 가장 가까운 loot를 선택한다.
  기존 데모 map에 `M3_MedkitLoot_0..3` 4개를 저장했다. 기존 Bag의 Medkit 외에 3개가 더 들어가면
  공간이 차므로 네 번째 pickup은 NoSpace가 된다. auto-stack·rotation·sort·split은 없다.
- 열린 WBP는 기존 Model → ChangeSet → ContainerVM → ItemVM/Widget 경로로 갱신한다.
  UI 제품 코드·WBP·Tick 정책·InventoryCore module 의존·Config·GDD·INVENTORY_DESIGN은 변경하지 않았다.
- 구조 결정과 비용은 [World loot ingestion](../architecture/017-world-loot-ingestion.md)에 정리했다.

### 실행 경로

- main이 설계·Actor/controller 구현·통합·실제 검증을 담당했다. 분리 가능한 Model 구현/테스트와
  이후 gameplay Automation은 native `gameplay-programmer`에게 순차 위임했다. 같은 tree에 동시 writer는 없었다.
- main은 candidate copy를 탐색 밖의 한 번으로 제한하고, footprint 범위로 scan을 줄였다.
  allocator 시작값에 의존하지 않는 assertion 및 자동 회전 금지 case도 보강했다.
- 독립 검토는 `cpp-reviewer`, `fork_turns: none`으로 요청했다. 역할 설정은 확인했으며 실제 실행
  model/effort metadata는 확인하지 않았다. 독립 reviewer는 원본 diff·코드·실행 로그를 검토한다.
