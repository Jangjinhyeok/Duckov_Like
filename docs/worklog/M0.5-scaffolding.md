# M0.5 — UE 프로젝트 스캐폴딩

기간: 2026-08-04 ~ 2026-08-05 · 상태: **완료**

## 목표

빈 repo에 UE 5.7 C++ 프로젝트를 세우고, GDD의 단방향 의존 원칙(`View -> ViewModel -> Model`)이
**규율이 아니라 빌드 시스템으로 강제되도록** 모듈을 구성한다.

인벤토리 로직은 구현하지 않는다 — 컴파일되는 최소 골격까지가 이 마일스톤이다.

## 작업 내역

### 프로젝트 CLAUDE.md (`f5b606f`)

커밋 규칙(Conventional Commits + 한글 본문), 코딩 규칙, 모듈 경계, 빌드 절차를 정의했다.
세부 컨벤션은 `docs/CONVENTIONS.md`로 넘겨 중복을 피했다 — 같은 규칙이 두 곳에 있으면
곧 불일치가 되고, CLAUDE.md는 매 세션 컨텍스트에 로드되므로 가벼울수록 좋다.

user-level CLAUDE.md의 "주석·커밋 메시지는 영어" 규칙을 프로젝트 차원에서 덮었다.
문서 상단에 override로 명시해 다음 세션에서 두 규칙이 충돌하지 않게 했다.

### Git LFS (`59f8980`)

UE 바이너리 에셋이 LFS 없이 커밋되면 히스토리에 박혀 되돌리기 어렵다.
그래서 프로젝트 파일보다 **먼저, 단독 커밋으로** 넣었다.

`lockable` 속성은 넣지 않았다 — 단독 개발이라 lock/unlock 왕복이 순수 비용이다.

```
검증: git check-attr filter -- (uasset/umap/png/gif/wav/fbx)  -> 전부 filter: lfs
검증: git check-attr filter -- (cpp/Build.cs/md/uproject/ini) -> 전부 unspecified
```

### UE 5.7 프로젝트 골격 (`b7f6b03`)

Blank C++ 템플릿, 스타터 콘텐츠 없음, Windows Desktop. **에디터로 직접 생성했다.**
프로젝트 브라우저가 `<경로>/DuckovLike/` 하위 폴더를 만들기 때문에 내용물을 repo 루트로 옮겼다.

```
검증: Build.bat DuckovLikeEditor Win64 Development -> Result: Succeeded (175.55초)
```

### 설계 문서 배치 및 작업 기록 규칙 (`9e83ee4`)

### InventoryCore 모듈 (`8dc2fcc`) — 이 마일스톤의 핵심

Model 모듈을 분리하고 UI 의존을 `Build.cs`에서 제외했다. 두 `Build.cs`의 대비:

```
InventoryCore: { "Core", "CoreUObject", "Engine" }
DuckovLike   : { "Core", "CoreUObject", "Engine", "InputCore", "EnhancedInput", "InventoryCore" }
```

`Public/`·`Private/` 분리는 소비자가 있는 모듈에만 적용했다. `DuckovLike`는 소비자가 없는
primary game module이라 평면 구조다 — 비대칭이 의도된 것이다.

```
검증: Build.bat -> Result: Succeeded (17.85초)
검증: 프로브 삽입 -> LNK2019 + LNK1120 -> Failed / 제거 -> Succeeded (5.78초)
```

## 막혔던 것

### Codex Builder 위임 실패 (5회)

토큰 절감을 위해 구현을 Codex에 위임하려 했으나 도구 경로에서 연속으로 막혔다.

| # | 원인 | 조치 |
| --- | --- | --- |
| 1 | HANDOFF 17.6KB가 `codex exec` argv 한계(8191자) 초과 | 명세를 별도 파일로 분리, 3.8KB로 축소 |
| 2 | risk tier를 헤딩에 써서 파싱 실패 → fail-closed HIGH | ` ```tiers ` 펜스 형식으로 교정 |
| 3 | `gpt-5.6-sol`이 codex-cli 0.141보다 신버전 요구 | CLI 0.141 → 0.146 업그레이드 |
| 4 | untrusted git repo → sandbox가 read-only로 강등 | `~/.codex/config.toml`에 trust 등록 |
| 5 | **sandbox가 `.git` 쓰기 차단** → 커밋 불가 | 우회 불가로 판단, 직접 구현으로 전환 |

5번이 결정적이었다. `git lfs install`이 `.git/hooks/pre-push: Access is denied`로 실패했고,
같은 이유로 UE 빌드(UBT가 엔진 디렉터리에 쓴다)도 막힐 것으로 봤다.

**교훈**: sandbox 안의 에이전트에게 "커밋까지 하라"는 요구는 성립하지 않는다.
파일 생성과 버전 관리를 분리해 맡기거나, 신뢰 설정을 먼저 확인해야 한다.

### orchestrator가 실패를 성공으로 판정

Codex가 모든 게이트를 `BLOCK`으로 보고했는데도 orchestrator는 `BUILT`를 출력하고 exit 0을 반환했다.
tier-gate가 advisory라 BLOCK을 통과시킨 것이다.

**교훈**: 도구의 exit code를 성공 신호로 믿지 않는다. 산출물을 직접 확인한다.
이 규칙은 `CLAUDE.md`의 빌드 절에 박아뒀다.

### headless 에디터가 4시간 종료되지 않음

모듈 로드 확인을 위해 `UnrealEditor-Cmd.exe ... -ExecCmds="Quit"`을 백그라운드로 돌렸는데,
**엔진은 51초 만에 정상 부팅했고 종료 명령만 먹지 않았다.** 로그를 보니 idle 루프에서
EOS SDK config 갱신만 반복하고 있었다.

```
LogInit: Display: Engine is initialized. Leaving FEngineLoop::Init()
LogLoad: (Engine Initialization) Total time: 51.47 seconds
```

**교훈**: `-ExecCmds="Quit"`은 unattended 에디터를 종료시키지 못한다. 쓰지 않거나 반드시 정리한다.
그리고 백그라운드 작업은 완료 알림만 기다리지 말고 중간에 확인한다.

## 모듈 경계 실측 — AI 서술을 교정한 기록

첫 시도에서 모듈 분리 후, **경계가 실제로 작동하는지 프로브를 넣어 확인했다.**

| `InventoryCore`에서 시도 | 결과 |
| --- | --- |
| `#include "Blueprint/UserWidget.h"` | **통과** |
| `UUserWidget* Ptr = nullptr;` (선언만) | **통과** |
| `UUserWidget::StaticClass()` (심볼 참조) | **LNK2019 → 빌드 실패** |

```
error LNK2019: unresolved external symbol Z_Construct_UClass_UUserWidget_NoRegister
fatal error LNK1120: 1 unresolved externals
Result: Failed (OtherCompilationError)
```

헤더가 통과하는 이유는 에디터 타깃이 `SharedPCH.UnrealEd`를 쓰는데 그 PCH에 UMG 헤더가
이미 들어 있기 때문이다. 경계를 만드는 것은 include path가 아니라 **`UMG.lib`가 링크 라인에
없다는 사실**이다.

AI가 처음 작성한 ADR에는 "컴파일 단계에서 즉시 죽는다"고 적혀 있었으나 **틀렸고**,
실측 결과로 교정했다. 경계는 즉각적이지 않지만 **우회는 불가능하다** —
UI 타입의 이름을 적어둘 수는 있어도 실제로 쓰는 코드는 한 줄도 빌드를 통과하지 못한다.

> 이 실측은 폐기된 첫 시도(`archive/m0.5-attempt1` 태그)에서 얻었고,
> **재시작 후 `8dc2fcc`에서 동일하게 재현했다.** ADR-000에 근거로 남겼다.

## 폐기한 것

첫 스캐폴딩 시도는 커밋 5개까지 완주했으나 **전량 폐기했다**(`archive/m0.5-attempt1` 태그로 보존).

폐기 이유는 결과물의 결함이 아니라 순서였다 — 프로젝트 규칙(CLAUDE.md)을 먼저 세우고
그 규칙 위에서 스캐폴딩을 다시 하는 편이 낫다고 판단했다. 실제로 재시작 후 커밋 메시지 형식이
바뀌었다(영어 → 한글 + 접두어).

- **모듈 경계** — `InventoryCore`(Model) / `DuckovLike`(게임). ADR-000, 상태 `Proposed`.
- **커밋·코딩 규칙** — CLAUDE.md. 한글 메시지 + Conventional Commits 접두어.
- **LFS 정책** — `lockable` 미적용.
- **작업 기록 규칙** — 마일스톤당 문서 하나, `AI 활용` 절 필수.

### 미결 사항

- **Automation Test 배치** — `InventoryCore` 내부(`WITH_DEV_AUTOMATION_TESTS`) vs
  별도 `InventoryCoreTests` 모듈. M1 시작 시 결정한다.
  별도 모듈로 가면 테스트가 Public 계약만 보게 되어 캡슐화가 강제된다.
- **ADR-001~008 승인** — M1 전에 `Proposed` → `Accepted`.

### 발견한 문제

- 킥오프 문서가 전제한 `docs/GDD.md`·`docs/INVENTORY_DESIGN.md`는 **존재하지 않았다.**
  Notion export가 합본 1개였고, 인벤토리 설계가 GDD 중간에 끼어 있어
  `## 6`·`## 11`·`변경 이력`이 각각 두 번 나왔다. 분리해서 해소했다.
- 문서의 **이미지 링크는 깨져 있다.** 의도된 상태다 — 이미지 자산은 별도로 처리한다.
- 에디터를 열 때마다 `Config/DefaultEngine.ini`에 `AndroidFileServer` 블록이 재생성된다.
  Windows 전용 프로젝트에는 불필요하다. 거슬리면 해당 플러그인을 비활성화하는 것이 근본 해결.
