## Context / Decision Question

기존 화면은 가운데 700×360 패널에 왼쪽 보관함·오른쪽 가방을 나란히 두고, 짙은 배경으로 장면을 가렸다.
원작(2026-10-14 관찰)은 왼쪽 캐릭터 패널(장비 슬롯 + 가방)과 오른쪽 창고 패널을 화면 양쪽에 두고, 장면을 거의 가리지 않으며,
패널 머리줄에 "가방 (22/85)"와 "전부 창고에 보관"·"정리" 버튼을 둔다. 베이스먼트에서는 Tab만으로 창고가 함께 열린다.
원작의 가방·창고는 한 칸짜리 목록형이지만, 이 프로젝트의 크기·회전 그리드 Model은 포트폴리오의 핵심이라 유지한다.

## Decision / Rationale

- **베이스먼트의 I는 창고까지, 레이드의 I는 가방만**: 사용자 결정. 024의 "보관함은 창고 오브젝트에서만"을 대체한다.
  레이드에서는 창고 패널 전체를 감춘다(잠금 제목을 보이는 대신). 창고 오브젝트의 F는 그대로 같은 화면을 연다.
- **원작 배치로 WBP 재구성**: 왼쪽 `CharacterPanel`(장비 제목, 가방 슬롯이 들어갈 `EquipmentSlot`, 가방 격자),
  오른쪽 `StashPanel`(창고 격자). 그리드 헤더는 "가방 (4/16)"처럼 차지한 칸/전체 칸을 보이고, 헤더 줄 오른쪽에 버튼을 겹쳐 둔다.
  배경은 옅게, 칸은 둥근 테두리, 아이템 칸은 수량·이름을 오른쪽 아래에 둔다. 1칸 너비의 긴 이름은 말줄임표로 줄인다.
- **BindWidget 이름은 유지**: `LeftGrid`(창고)·`RightGrid`(가방)·`SortLeftButton`·`SortRightButton`은 테스트와 코드 100여 곳의 계약이라
  이름을 바꾸지 않고 배치만 바꿨다. 헤더 주석에 실제 위치를 적었다.
- **"전부 창고에 보관" 버튼**: 원작 버튼이고, 이미 있는 `TryTransferAll`(원자적 전체 이전)로 실제 동작한다.
  View → `UInteractionViewModel::TransferAll` → Model로 연결해 단방향을 지킨다. 실패하면 기존 실패 문구 자리에 이유를 보인다.
  창고가 잠기면 비활성이고, 비활성 버튼 delegate를 직접 불러도 막힌다.
- **닫기는 아래 가운데, 방향 키 이동은 WBP에 명시**: 원작은 닫기 버튼이 없지만 CommonUI focus 대상이 필요하다.
  원작의 퀵슬롯 자리(아래 가운데)에 두었다. 패널이 좌우로 바뀌어 기본 공간 탐색이 방향과 맞지 않으므로
  닫기 ↑ 가방 정리, 가방 정리 ← 전부 보관 / → 창고 정리, 버튼들 ↓ 닫기를 명시 규칙으로 저장했다.
- **레이아웃은 명령으로 만든다**: `InventoryAssets.Create`와 새 `InventoryAssets.RebuildWidgets`가 같은 빌더 함수를 쓴다.
  재생성 명령은 Item·Grid·Screen WBP 세 개를 지운 뒤에만 실행되고 덮어쓰지 않는다. DataTable과 데모 맵은 건드리지 않는다.
- **툴팁**: 원작처럼 조작 키 안내를 덧붙인다("드래그: 이동 · 드래그 중 R: 회전", 수량이 2 이상이면 "Shift+클릭: 스택 분할").
  원작의 별도 툴팁 패널(속성 표 + 키 열)은 아이템마다 위젯을 만들어야 해 이번에 넣지 않았다.

## Alternatives / Trade-offs

- **원작처럼 목록형으로 바꾸기**: 원작과 더 닮지만 크기·회전·배치 규칙(M1 Model과 테스트)이 포트폴리오의 핵심이라 버렸다(사용자 지적).
- **BindWidget 이름을 위치에 맞게 바꾸기(StashGrid/BagGrid)**: 코드가 읽기 쉬워진다. 테스트·코드 100여 곳과 WBP 바인딩을 함께 바꿔야 해
  이번 화면 개편과 섞지 않았다. 이름과 위치의 불일치는 헤더 주석으로 남겼다.
- **기본 공간 탐색에 맡기기**: 규칙이 없어 간단하다. 패널 높이와 해상도에 따라 ↑/↓/←/→의 도착 버튼이 달라져 기존 입력 lifecycle 테스트가 깨졌다.
- **WBP를 그대로 두고 C++에서 레이아웃 재배치**: 에셋 재생성이 없다. 디자이너에서 보이는 구조와 실행 구조가 달라진다.

## Consequences / Accepted Costs

- 화면의 BindWidget 계약에 `StoreAllButton`(필수), `StashPanel`·`EquipmentSlot`(선택)이 늘었다. 기존 바인딩은 그대로다.
- 데모 맵의 Raid에서도 창고 패널이 감춰진다(같은 화면 위젯).
- `Duckov.UI.PIEInputLifecycle`의 방향 키 검사를 새 배치에 맞게 바꿨다. 키보드로 두 정렬과 닫기에 닿아 실행된다는 계약은 같다.
- 이름 줄임은 영문 행 이름 기준 5글자 초과면 4글자 + 말줄임표다. 한글 이름이 들어오면 폭 기준으로 다시 정한다.
- 가방 장착 버튼은 코드에서 만드는 기존 기본 스타일 그대로다.
- 명시 이동의 대상이 비활성이면 그 방향은 움직이지 않는다(엔진은 다른 버튼으로 대신 가지 않는다). 레이드에서 가방 정리의 ←(전부 보관 비활성)·→(창고 패널 감춤)가 그렇다. ↓로 닫기, 닫기에서 ↑로 가방 정리는 항상 되므로 focus가 갇히지는 않는다.
- `InventoryAssets.RebuildWidgets`는 디스크의 파일만 확인한다. 같은 에디터 세션에서 WBP를 연 채 파일만 지우고 실행하면 이름이 겹칠 수 있어, 새 에디터 process에서 실행한다.

## Revisit Conditions

- 아이템 표시 이름·아이콘이 데이터에 생길 때: 칸 표시와 이름 줄임을 다시 정한다.
- 원작 수준의 툴팁 패널이 필요할 때: 공유 툴팁 위젯 하나를 재사용하는 방식을 검토한다.
- 화면 탭(캐릭터·지도 등)이 생길 때: 위 가운데에 원작의 탭 줄을 두고 닫기 위치와 방향 키 규칙을 다시 정한다.
